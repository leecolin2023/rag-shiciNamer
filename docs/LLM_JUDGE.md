# LLM 评审层 · 使用方法（D-011 的 L3，人工/大模型主观判断层）

程序到这里为止（AGENTS.md 待办已注明）。它产出**可核对的证据**，
但语义、谐音、俗雅是主观层——按项目哲学不做客观模拟（D-003），
交给大模型/人来判。流程三步：

```bash
# ① 生成评审档案（重跑口径后可随时刷新）
python tools/llm_dossier.py outputs/nie_male_l3.json --top 100
# ② 打开 outputs/llm_dossier_*.md，全选复制
# ③ 用下面的提示词 + 档案，投给任意大模型（或直接在本项目对话里让我评）
```

## 提示词模板（随档案一起发给大模型）

```
你是起名评审。下面是程序从古典诗词中摘出、按客观口径排序的候选档案。
你的任务不是重新排序，而是做程序做不了的三件事：

1. 语义与意象：词义是否立体、意象是否成画面、有无现代歧义或俗感
2. 谐音与全名听感：结合"姓氏+名"连读，检查不雅谐音、外号风险、拗口
3. 叙事碎片识别：出处原句是疑问句/叙事/古人名/官职/地名的，名次再高也要降级

硬性规则：
- 只能使用档案里的事实（出处、原句、人口、声调），不得编造或"补充"出处
- 每个推荐必须引用它的原句
- 名次是证据不是答案：可以把 #800 提到 #50 前，但必须说明理由
- 原句语境悲伤（如《九章》多哀句）要标注，但单字词义正的名字仍可推荐，由父母定夺
- 输出三部分：①推荐 Top5（全名+出处+理由）②淘汰名单（名字+一句理由）
  ③你还缺什么信息

[在此粘贴档案]
```

## 为什么这样设计

- **不违反 D-003**：大模型的判断在程序排序之外，不产生分数回流 `rank.order`。
- **防编造**：LLM 最危险的失败是给假出处（"出自《诗经》"实际不存在）。
  档案里只给原文，提示词强制引用，核对成本为零。
- **谐音是 LLM 的独特价值**：P1 待办的谐音检测（毛泊涵≈毛伯涵类）在程序里
  很难做全，大模型天然擅长——但只对**档案里有的名字**负责。
